## 2. 功能覆盖

### 2.1 LLM 客户端与解析器

- `QwenClient` 支持 OpenAI 兼容的非流式 `chat/completions` 调用。
- 支持 SSE 流式输出、60 秒超时、失败重试 1 次，并返回 `response`、`usage`、`latency_ms`。
- `parse_json_response()` 支持标准 JSON、```json 代码块、文本中的平衡花括号，以及无法解析时降级为原文。
- 空回复在处理器中重试 1 次，仍为空时降级为标准拒答话术。

专项测试已验证结构、超时异常语义和 4 类 JSON 解析场景；真实模型调用不在当前专项测试中强制依赖有效 API Key。

### 2.2 Few-shot 与 Prompt

- 已提供 9 个意图/场景块，包括价格、技术支持、故障排查、使用指南、产品比较、购买流程、账号管理、澄清和通用场景。
- 示例选择器最多选 3 个示例，澄清场景优先选择澄清示例。
- Prompt 包含角色定义、知识库、历史上下文、意图置信度、Few-shot、JSON 回复约束和当前问题。
- Prompt 设定 8000 字符硬上限，并对知识库、历史和 Few-shot 内容提供裁剪兜底。

本轮专项测试确认示例选择、Prompt 主要字段、意图筛选和长度上限有效。任务书原文要求每种意图 3-5 个示例；当前实现以字符串示例块组织，自动化测试没有对 7 个必需意图逐一计数并验证每类示例数量，该项仍需后续补强测试。

### 2.3 路由与处理器

路由优先级实现为：

1. 转人工
2. 澄清（最多两次）
3. FAQ 直接命中
4. LLM 生成
5. 多次澄清后低置信度降级人工

处理器覆盖澄清问题、知识库 FAQ 来源标注、LLM 生成和转人工话术。知识库检索支持技术支持/故障排查以及购买流程/价格等跨类别映射，避免意图名称与知识分类不一致导致漏答。

专项测试已覆盖路由 5 个场景和处理路径 3 个场景。

### 2.4 编排器与 WebSocket

真实服务下 8 个 E2E 用例全部通过：

| 用例 | 结果 | 观察 |

| 直接价格咨询 | ✅ | 命中价格知识库并返回来源内容 |
| 短问题 + 上下文 | ✅ | 第二轮能结合前文返回价格信息 |

WebSocket 同时支持 JSON 消息和裸文本消息，并推送 `waiting`、`thinking`、`response` 状态。回复元数据包含 `intent`、`engine`、`path`、`sources` 和澄清标记。
