## 5. 回归原因判断

当前规则引擎将“支持YouTube吗”识别为 `product_comparison`。该意图会联合检索产品、购买和使用类别；在没有 YouTube 相关知识证据时，路由仍允许进入 LLM 生成路径。Prompt 中虽然要求“知识库没有的信息回复暂时无法回答，需要人工介入”，但没有程序级硬约束阻止模型生成知识库外结论。

因此，当前实现对知识库外问题的拒答依赖模型自觉遵守 Prompt，稳定性不足。该问题直接触及任务书暗卷“‘YouTube直播’应拒答”，应作为下一次修复的阻断项处理。

## 7. 整改后遗留项

1. 修复知识库外问题的程序级拒答约束，至少保证“支持YouTube吗”稳定返回拒答并转人工。
2. 为该场景增加自动化回归测试，直接断言 `orchestrator.process("支持YouTube吗", {})` 不得返回肯定性平台支持结论。
3. 在进入 LLM 路径前判断知识库相关度或有效命中证据；无相关证据时直接返回标准拒答话术，或在生成后对来源为空/相关度为零的结果强制拒答。
4. 收紧准确率评估规则，区分“真正回答问题”和“仅命中关键词但实际转人工”。
5. 重新执行完整真实 WebSocket E2E 和 UI 黑盒检查，确认 YouTube 场景及对应截图恢复一致。
