## 阻塞 / 必须修

**B1 半死端点：整轮静默卡住，不抛错、不出题（阻塞直播）**
- 判据「首问即挂才算连续失败」（:574），失败计数在 :577 清零。只要一个切片里有任何一次 ask 成功，失败计数就清零。
- 实测：每个切片的第 2 题固定失败（模拟某个 prompt 稳定解析失败、或限流只放行首个请求）。20s 内 0 题出货、pose 一直不返回、没有抛错，蓝方按约 4.3 req/s 持续收到请求。
- 后果：直播局停在出题这一步，群里什么都看不到，也不会进入「失败只记录」的收尾。
- 修法（二选一，或都做）：
  - 计数改成「连续 K 个切片都没完整交货」；
  - 或者改成切片内逐题重试：一题失败只重试这一题，不整片重来。这样同时解决下面的效率问题。
  - 另外 pose 要有总墙钟上限：等某一题超过 T 秒就抛 BlueExhaustedError。
- 附带的效率问题：15% 逐题失败时，一个切片约 80% 会整片重来。实测 n=45 时 fill_start 42 次、fill_end 只有 5 次，单次等题最长 9.4s（假端点每题 0–20ms）。真端点约 16s/题，算下来一批可能要几十分钟。
